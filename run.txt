ANGAAR DHABA — HOW TO RUN THIS PROJECT
========================================

This project has two parts:
  1. FRONTEND — the website (index.html, menu.html, waiter.html, etc.)
     Already live on Vercel: https://hotel-rag-gen-glb.vercel.app/
  2. BACKEND — stores orders in a real database, so the customer's phone,
     the waiter's phone, and the counter PC all see the same live order
     data. The kitchen isn't a screen at all — it gets a physical printed
     ticket per order via print_jobs/the Print Agent (see Step 7 below).

IMPORTANT — there are currently TWO backend implementations in this repo:

  server/       Node.js + MongoDB. This is what's ACTUALLY LIVE right now
                (deployed on Render, orders.js currently points at it).

  server-php/   PHP + MySQL. Newly built to run on MilesWeb (cPanel/shared
                hosting), since that plan doesn't support deploying
                MongoDB or a Node.js server. Fully built and tested, but
                NOT deployed yet — the live site is still running on the
                Node version above until someone completes the steps
                below and re-points orders.js at it.

Once server-php/ is deployed and orders.js is switched over, the old
server/ and print-agent/ (Node.js) folders are no longer needed and can
be removed — they're left in place for now so the live site keeps
working in the meantime.

The steps below are for deploying the NEW PHP + MySQL backend to MilesWeb.


STEP 1 — Create the MySQL database (cPanel)
------------------------------------------------
1. Log in to your MilesWeb cPanel.
2. Find "MySQL® Databases" and open it.
3. Under "Create New Database", type a name (e.g. angaardhaba) and click
   Create. cPanel will rename it to something like
   yourcpaneluser_angaardhaba — that's normal.
4. Scroll to "MySQL Users" -> "Add New User". Pick a username, click
   "Password Generator" to make a strong password, and COPY that password
   somewhere safe (a password manager, not chat, not this conversation).
5. Scroll to "Add User To Database". Pick the user and database you just
   made, click Add, then on the next screen tick "ALL PRIVILEGES" and
   click "Make Changes".


STEP 2 — Load the database tables
--------------------------------------
1. In cPanel, open "phpMyAdmin".
2. On the left, click your database name.
3. Click the "Import" tab at the top.
4. Click "Choose File" and select: server-php/db/schema.sql (from this
   project folder on your computer).
5. Click "Go" at the bottom. You should see a success message and new
   tables appear on the left: orders, order_items, print_jobs,
   invoice_seq, staff_logins (per-waiter/counter PIN login).


STEP 3 — Upload the backend code
--------------------------------------
1. In cPanel, open "File Manager" (or use an FTP program if you prefer).
2. Upload the ENTIRE server-php folder to your hosting.
3. ALSO upload menu-data.json — it needs to sit one folder level ABOVE
   server-php, i.e. if server-php ends up at:
     /home/yourcpaneluser/api/server-php/
   then menu-data.json needs to be at:
     /home/yourcpaneluser/api/menu-data.json
   (The backend reads menu-data.json directly to know each dish's price
   and which printer station it belongs to.)
4. If you want this reachable as its own address like
   api.yourdomain.com, set that up under cPanel's "Subdomains" or
   "Domains" tool, pointing at the folder from step 3.


STEP 4 — Configure the backend
------------------------------------
1. In File Manager, go into server-php/config/
2. Make a copy of .env.example and rename the copy to: .env
3. Edit .env and fill in:
     DB_HOST=localhost
     DB_NAME=yourcpaneluser_angaardhaba   (from Step 1)
     DB_USER=yourcpaneluser_angaardhaba   (from Step 1)
     DB_PASSWORD=<the password you saved in Step 1>
     ALLOWED_ORIGINS=https://hotel-rag-gen-glb.vercel.app


STEP 4b — Add waiter/counter staff logins
------------------------------------------------
Each waiter and each counter person gets their own PIN, which both logs
them in and sends them straight to their console (waiter.html or
counter.html) — no shared PIN, no picking your name from a list. In
phpMyAdmin, run one INSERT per person against the staff_logins table:
     INSERT INTO staff_logins (pin, name, role, created_at)
     VALUES ('1234', 'Rahul', 'waiter', UNIX_TIMESTAMP()*1000);
role is either 'waiter' or 'counter'. To deactivate someone without
deleting their row: UPDATE staff_logins SET active = 0 WHERE pin = '1234'.
The old shared STAFF_PIN (Step 4 above) still works too — it's the
fallback for anyone who isn't a waiter/counter, e.g. to reach staff.html
for table-qr.html.


STEP 5 — Test the backend
-------------------------------
Open this in a browser (using your actual domain from Step 3):
     https://your-backend-url/api/health.php
You should see:
     {"ok":true,"message":"Angaar Dhaba API is running"}
If you see a database error instead, double-check Step 4.


STEP 6 — Tell the website where the backend lives
-----------------------------------------------------
1. Open the file: orders.js  (in the main project folder, not in
   "server-php")
2. Near the top, find this line:
     const API_BASE = 'https://your-php-backend-url';
3. Replace the URL with your real backend URL from Step 3.
4. Save, commit, and push to the ek-punjab branch.
5. Vercel will automatically redeploy the website with the new setting.

This is the step that actually switches the live site over from the old
Node/MongoDB backend to the new PHP/MySQL one.


HOW TO TEST IT'S ACTUALLY WORKING
------------------------------------
Open the site on two different devices at the same time (e.g. your
phone and a laptop, or two browser windows in "incognito" so they don't
share storage):
  - Device A: open menu.html, set a table number, add a dish, place order
  - Device B: open waiter.html (log in with a waiter PIN — see Step 4b below)
You should see the order appear on Device B within a few seconds (this
version checks for updates every few seconds rather than pushing
instantly — shared hosting can't run the always-on connection the old
Node version used, but the difference is barely noticeable in practice).
There's no on-screen kitchen queue to check — confirm the kitchen side by
looking for a new row in the print_jobs table (station=KITCHEN/BAR), which
is what the Print Agent picks up and sends to the physical ticket printer.


STEP 7 (OPTIONAL) — PHYSICAL RECEIPT PRINTING (Kitchen / Bar / Billing)
---------------------------------------------------------------------------
Only needed once you have real thermal printers set up at the restaurant.
Kitchen and Bar tickets never show prices; the Billing printer is the
only one that does, and it only prints when the counter clicks "Print
Bill".

This CANNOT run on the web host — printers sit on the restaurant's
private network (192.168.x.x) which a website can't reach. Instead, a
small PHP program called the "Print Agent" runs on a computer inside the
restaurant (e.g. the billing PC), on the same network as the printers.

1. Find each printer's IP address (usually via a self-test page or the
   printer's own network menu) and give it a fixed/static IP on the
   restaurant's router.
2. On the restaurant's PC, if it doesn't already have PHP, download a
   PHP zip from https://windows.php.net/download/ and extract it — no
   installer needed.
3. In print-agent-php/:
     copy .env.example to .env
     fill in BACKEND_URL (your real backend URL from Step 3) and each
     printer's IP
4. Run it:
     php agent.php
5. Full details, including how to test with DRY_RUN before wiring up
   real printers, and how to keep it running in the background, are in
   print-agent-php/README.md.


RUNNING THE BACKEND ON YOUR OWN COMPUTER (optional, for testing changes)
-----------------------------------------------------------------------------
You'll need PHP and a local MySQL server (e.g. XAMPP, which bundles
both) installed on your computer.
  cd server-php/config
  copy .env.example to .env
  fill in DB_HOST/DB_NAME/DB_USER/DB_PASSWORD for your local MySQL
  load db/schema.sql into your local database (phpMyAdmin's Import tab)
  cd ..
  php -S localhost:5050

The backend will start on http://localhost:5050


RUNNING THE FRONTEND ON YOUR OWN COMPUTER (optional)
---------------------------------------------------------
From the main project folder:
  python -m http.server 5000
Then open http://localhost:5000/index.html in your browser.
